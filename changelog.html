PyFixest 0.70.0

Changelog

import pyfixest as pf
from pyfixest.report.utils import rename_categoricals

df = pf.get_data()

fit1 = pf.feols("Y ~ X1", data = df)
fit2 = pf.feols("Y ~ X1 + X2", data = df)
fit3 = pf.feols("Y ~ X1 + X2 | f1", data = df)

TL;DR

  • Varying slopes. | f1[X2] estimates a separate slope on X2 for each level of f1, in feols(), fepois() and feglm().
  • Formulas are parsed by formulaic. The fitted model spec is reused for predict() and fixef(), so new data is encoded exactly like the estimation data, and predict(newdata=...) now works with i(), poly() and interacted fixed effects. Along with it come new formula spellings:
    • Fixed-effect interactions are written f1:f2.
  • New IV syntax. Instrumental variables are written in brackets, Y ~ X1 + [X2 ~ Z1], which also accepts interacted endogenous terms such as X2:Z2. The old Y ~ X1 | X2 ~ Z1 syntax still works, but it emits a deprecation warning and will be removed in a future release.
  • New default demeaner. LSMR from the within package with an adaptive preconditioner.
  • Typed results. Fitted models expose their state as documented components such as fit.coeftable, fit.variance_covariance and fit.model.
  • Also new: anytime-valid inference (SAVI), Wor‹◊ tables from etable(), weights and offsets in feglm(), clustering on three or more variables, and Python 3.15.
  • Many correctness fixes, several of which change results: ritest() p-values, i() reference levels, weighted RMSE, the IV first stage, decompose() and quantreg’s cfm2 process. See Bug fixes.
  • Before you upgrade: pyfixest needs Python 3.11+ and newer formulaic and pandas; model names in multiple estimation changed; fixef() returns a DataFrame; most private attributes such as fit._se are gone; f1^f2 and Y ~ X1 | X2 ~ Z1 are deprecated. See Breaking changes and Migrating Fitted-Model Attributes.

New Features

Varying Slopes

feols() (including IV), fepois() and feglm() accept slopes that vary by fixed-effect level. f1[X2] absorbs f1 and a slope on X2 for each of its levels; f1[[X2]] absorbs only the slopes. Varying slopes need the default within demeaner, and predict(), fixef(), wildboottest(), ritest(), decompose(), did2s() and CRV3 or HAC inference don’t support them yet (#1929, #1930, #1931, #1999).

pf.feols("Y ~ X1 | f1[X2] + f2", data=df).tidy()
Estimate Std. Error t value Pr(>|t|) 2.5% 97.5%
Coefficient
X1 -0.927055 0.056855 -16.305595 0.0 -1.038637 -0.815472

Formulas Parsed by formulaic

We no longer split formula strings by hand. Formulas go to formulaic, and the fitted ModelSpec is reused to build model matrices for predict() and fixef(). This removes a class of bugs where new data was encoded differently from the estimation data. Most terms now follow formulaic’s syntax (#1362, #1437).

  • predict(newdata=...) works with i(), poly() and interacted fixed effects. Unseen levels predict NaN.
  • Fixed-effect interactions are written f1:f2.
  • sw(), csw(), sw0() and csw0() accept a single argument, so | sw0(f1) fits models with and without f1 (#1830).

The old spellings still work with a deprecation warning and will be removed in a future release. The behaviour changes that come with the new parser are listed under Breaking changes.

New IV Syntax

Instrumental variables are written as a bracketed block in the main formula, Y ~ X1 + [X2 ~ Z1], combined with fixed effects as Y ~ X1 + [X2 ~ Z1] | f1 (#1362). The block accepts interacted endogenous terms such as X2:Z2 (#1890), and the main formula sets the intercept of both stages (#1998).

The old Y ~ X1 | X2 ~ Z1 syntax still works, but it emits a deprecation warning and will be removed in a future release.

within LSMR Is the Default Demeaner

The default demeaner is now LSMR from the within Python package (within-py, a new required dependency), replacing the Rust crate compiled into pyfixest. Rust MAP is still available through MapDemeaner().

The default preconditioner="auto" now selects within’s adaptive preconditioner. It starts with a cheap diagonal preconditioner and builds additive Schwarz only when convergence stalls, which skips Schwarz’s setup cost on well-connected fixed effects where it rarely pays off. fepois() and feglm() still reuse the preconditioner across IRLS iterations (#1920, #1922, #1923).

Typed Fitted-Model State

Fitted models expose what they computed as documented components instead of private attributes (#1533, #2028):

Component Contents
fit.model formula, dependent variable, fixed effects, estimator, sample split
fit.options estimation options: ssc, weights, demeaner, storage settings
fit.sample_info number of observations and dropped rows by reason
fit.coeftable estimates, standard errors, t-statistics, p-values, confidence intervals
fit.variance_covariance covariance matrix, small-sample corrections, cluster counts
fit.sandwich scores, Hessian and bread
fit.fitstat RMSE, R² measures, deviance, log-likelihoods
fit.fitted_values in-sample predictions on the link and response scale
fit.collinearity columns dropped as collinear
fit.fixef_counts, fit.fixef_estimates fixed-effect level counts; fixed-effect estimates after fixef()
fit.first_stage IV first stage and its diagnostics
fit.wald joint Wald test from fitting, replaced by each wald_test() call
fit.capabilities inference and post-estimation methods the model supports
fit.solution quantile-regression solver state

The components that describe the model and its sample survive store_data=False and lean=True.

Safe Anytime-Valid Inference (SAVI)

evalue(), pvalue_savi() and confint(inference_type="savi") return e-values, sequential p-values and confidence sequences for linear regression, following Lindon et al. (2026) (#1386).

Smaller Additions

  • etable(type="docx") returns or saves editable Word tables, styled through docx_style (#1541).
  • feglm() accepts weights, weights_type, offset and family="poisson". Offsets can be expressions such as offset="log(exposure)" (#1349, #1458).
  • fepois() converges faster thanks to step-halving and warm starts (#1347).
  • Cluster-robust inference accepts three or more cluster variables, e.g. vcov={"CRV1": "firm + year + region"} (#1599).
  • tidy(), confint() and summary() gain an inference_type argument. confint(inference_type="simult") replaces confint(joint=True) (#1398).
  • Python 3.15 is supported. On 3.15, plots use matplotlib because lets-plot has no compatible release yet (#2030).

Breaking Changes

Requirements

  • Python 3.11 or newer (#2029).
  • formulaic>=1.2.2,<1.3, pandas>=2.3.3, narwhals>=1.17 and the new within-py>=0.4,<0.5 (#1895, #1946, #1954, #1920).

Formulas and Model Names

  • Model names in multiple estimation are canonical formulas. "Y ~ sw(X2+X1, X1)" now names its models "Y ~ 1 + X2 + X1" and "Y ~ 1 + X1". Update rename_models mappings and lookups into all_fitted_models. Expansions that produce the same model twice estimate it once and warn (#1362, #1873, #1890).
  • fixef() returns a DataFrame with columns variable, code, level and coefficient instead of a nested dict. With two or more fixed effects, the reference levels of the second and later ones are listed with coefficient 0 (#1362).
  • The main formula sets the intercept for both IV stages; a 0 or 1 inside the IV block is ignored (#1998).
  • Fixed effects must be data columns, or : interactions of them, whose names are valid Python identifiers. Transforms and object-dtype columns are rejected, and predict() requires the same dtype as at fit time (#1898, #1902).
  • log() in formulas is now np.log. Zeros are counted as infinite rather than missing, and numpy warns on zero or negative inputs. Estimates are unchanged (#1806, #1869).
  • Some malformed formulas raise formulaic.errors.FormulaSyntaxError, which is unrelated to pyfixest.errors.FormulaSyntaxError; catch both (#1362).
  • factor_interaction moved to pyfixest.estimation.formula.transforms.factor_interaction (#1362).

Fitted Models and Post-Estimation

  • Most private attributes from 0.60 are removed. Accessing one, e.g. fit._se, raises an AttributeError that points to the migration guide; use fit.coeftable.se instead. Names used by released versions of marginaleffects and maketables keep working, and the IV attributes _model_1st_stage, _f_stat_1st_stage and _eff_F keep working with a deprecation warning. See Migrating Fitted-Model Attributes (#2028).
  • pf.ssc() returns a frozen Ssc instead of a dict (dicts are still accepted as input). pf.get_ssc() takes an Ssc and DegreesOfFreedomCounts and returns a SmallSampleCorrection. wald_test() returns a WaldTest instead of a Series (#1595, #1591).
  • feglm().resid() returns response residuals y - mu by default; the old working residuals are resid(type="working") (#1349).
  • feglm(family="gaussian") now reproduces feols() exactly, including its small-sample correction (#1352).
  • Passing data to vcov() raises ValueError. It silently misaligned rows in cluster-robust standard errors (#1825, #1956).
  • vcov and vcov_kwargs are checked before fitting, so a misspelled estimator or a missing cluster column fails early with ValueError (#1577).
  • Several methods that ran on unsupported models and returned wrong numbers now raise: ccv() on weighted models; Feols.update() with inplace=True, weights or IV; CRV3 on non-Poisson GLMs; ritest() on models other than OLS and Poisson; wildboottest() on IV and non-OLS models; decompose() on non-feols models or with multiway clustering; predict(), wildboottest(), ccv(), decompose() and vcov() updates on did2s() fits; and predict(se_fit=True) for GLMs and quantile regression (#1516, #1620, #1726, #1698, #1652, #1983).
  • Invalid arguments to ccv(), ritest(), event_study(), did2s() and lpdid() raise ValueError or TypeError instead of AssertionError. Every warning now has an explicit category and points at your code rather than pyfixest internals (#1723).
  • Methods that need data removed by store_data=False or lean=True raise MissingModelDataError (#1540).
  • pyfixest no longer uses or reseeds NumPy’s global random generator. Data from get_blw(), get_sharkfin() and get_panel_dgp_stagg() changes, and ccv() and simultaneous confidence intervals need seed= to be reproducible (#1705).
  • The model classes take options= and sample_split= constructor arguments instead of many loose keyword arguments (#1598, #1719).
  • did2s() rejects a second stage without an intercept, IV formulas and multiple estimation (#1918).

Demeaner

  • preconditioner="auto" now means adaptive, so results can differ slightly from 0.60. Pass preconditioner="additive" for the old behaviour (#1922).
  • pf.Preconditioner is within.Preconditioner. Its variant is replaced by config, and build_time_seconds is renamed build_duration_seconds. Preconditioners pickled with older versions can’t be loaded (#1920).

Deprecated

These still work and emit a warning (#1362, #1437, #1398, #1704, #2028):

  • Y ~ X1 | f1^f2: write Y ~ X1 | f1:f2.
  • Y ~ X1 | X2 ~ Z1: write Y ~ X1 + [X2 ~ Z1].
  • Y + Y2 ~ X1: write sw(Y, Y2) ~ X1.
  • confint(joint=True): use confint(inference_type="simult").
  • FixestMulti.FixestFormulaDict: use fit.model.parsed_formula.
  • fit.get_performance(): use fit.fitstat.
  • fit.n_separation_na: use fit.sample_info.
  • maxiter, tol and separation_check on GLM fits: use fit.options.

Removed

  • The demeaner_backend, fixef_tol and fixef_maxiter arguments; use the Demeaner API from 0.60 (#1332).
  • The JAX demeaner and solver, and the SciPy and CuPy LSMR backends. On GPU, use LsmrDemeaner(backend="torch", device="cuda") (#1333, #1334, #1718).
  • FeolsCompressed (#1336) and pf.dtable(); use maketables.DTable() instead (#1404).
  • The fit.FixestFormula attribute (use fit.model) and the callable Feiv.first_stage(); fit.first_stage is now a component (#1610, #1588).
  • FixestFormulaParser, model_matrix_fixest(), the pyfixest.estimation.feols_, feiv_ and fepois_ modules (import Feols, Feiv and Fepois from pyfixest.estimation instead), and several unused helpers in pyfixest.utils (#1607, #1704).

Bug Fixes

Inference

  • ritest() now permutes the observed treatment. It used to draw treatments uniformly from the distinct values, which changed the share treated and typically made p-values too small. This also affects rwolf() and wyoung() with sampling_method="ri". With cluster=, a treatment that varies within a cluster raises ValueError (#1964, #1965).
  • ritest(type="randomization-t"), ritest(cluster=...) and ccv() keep the fitted model’s covariance estimator and small-sample corrections, and the randomization t-statistic is centred at the null (#1986–#1989).
  • ritest() rebuilds treatment-dependent interactions on every draw (#1979), and its fast algorithm works with interacted fixed effects (#1780, #1866).
  • vcov({"CRV3": ...}), ritest() and ccv() refit with all the original estimation options. Before, a Poisson offset and options such as context or drop_intercept were dropped (#1709, #1711).
  • CRV3 on event_study() fits refits with feols() instead of Poisson (#1619).
  • wildboottest() and decompose() leave out covariates that the fit dropped as collinear (#1778, #1867), and wildboottest() requires param instead of returning p = 0 (#1959, #1969).
  • confint() with keep or drop could attach intervals to the wrong coefficients (#1397).
  • The RMSE of weighted fits divides by the sum of weights (#1883, #1884).

IV

  • The first stage uses the second stage’s sample, options and full covariance estimator. Before, two-way clustering fell back to one-way clustering, and vcov="NW" or "DK" failed (#1710).
  • Redundant instruments no longer change the first-stage F or effective F (#1996). Instruments that don’t identify an endogenous variable raise IVIdentificationError (#1891, #1992, #1993).
  • Covariates named like generated values (X2_hat), misplaced IV blocks, and | inside IV expressions are handled correctly (#1736, #1766, #1890, #1834).

Formulas

  • Multiple estimation no longer reuses demeaned values from a different expression that happens to have the same column name (#1762, #1914).
  • i() fixes:
    • a boolean second variable fits one slope per level (#1756, #1907);
    • levels come from the data before missing rows are dropped, and unused categories of a Categorical are ignored, which fixes the reference level in some models (#1769, #1912);
    • without an intercept, every interaction cell is kept (#1767, #1942);
    • C(k) marks a numeric second variable as a factor, so i(a, C(k)) interacts two factors instead of fitting slopes. ref2 and bin2 no longer turn a numeric second variable into a factor and raise instead (#1770, #1804, #1943);
    • bin is validated (#1771, #1945);
    • factor-by-factor interactions work with NumPy 1.25 (#1909, #1952).
  • Formulas whose terms produce duplicate column names raise instead of keeping only the last column (#1928, #1947).
  • sw() and friends work across several lines and with a space before the parenthesis (#1810, #1847). Stepwise terms keep their grouping under :, * and - (#1828).
  • log() accepts nullable Float64 and Int64 columns (#1807, #1829).
  • weights= accepts column names with spaces or operators (#1815, #1844). Zero weights are dropped with a warning instead of raising (#1800, #1864).

GLM and Poisson

  • Frequency weights work in fepois() and feglm() (#1521).
  • Separation checks: Gaussian feglm() no longer drops groups as separated (#1978, #1982); logit and probit also drop groups whose outcomes are all 1, and ignore separation_check=["ir"] with a warning (#1623, #1982); the iterative-rectifier check keeps rows aligned after missing values and respects the formula context and demeaner (#1777, #1799, #1846, #1841, #1877, #1454).
  • fixef() and predict() for fixed-effects-only GLMs work on the link scale instead of the response scale (#1622).
  • fepois(context=0) finds functions defined in your code (#1656, #1835).
  • fixef(), predict(), decompose() and the LSQR solver raise NonConvergenceError instead of returning unconverged estimates (#2009, #2012).

DiD and Decomposition

  • did2s() standard errors use the first-stage fixed-effect encoding, handle collinear second-stage columns, and reject missing cluster IDs or fewer than two clusters (#1758, #1811, #1812, #1918, #1865, #1980). It also explains which first-stage fixed effects can’t be estimated (#1244, #1368).
  • event_study(estimator="saturated") uses the xfml covariates, which it used to ignore (#1966, #1975).
  • decompose() no longer depends on the order of regressors (#1967, #1974), keeps mediators left out of combine_covariates in an Other group (#1962, #1972), and draws independent bootstrap samples in parallel, so seed gives the same result for any nthreads (#1696).

Other

  • quantreg(multi_method="cfm2") uses the density-weighted Hessian. Before, the updates mostly shifted the intercept (#1745, #1842).
  • LsmrDemeaner(backend="torch") raises ImportError when PyTorch is missing instead of silently using MAP (#1718).
  • iplot() no longer mistakes regressors with :: in their name for i() terms (#1564).
  • Fitting models no longer imports Matplotlib, Seaborn or Lets-Plot; they load only when you plot (#1483).

Documentation

  • Tutorials, the README and docstrings use the new formula spellings, and the formula tutorial maps each deprecated form to its replacement (#1836).

Contributor Workflow

  • New pixi tasks: bench-estimation for before/after timing, test-r-fixest-fast for a quick comparison with R, and test-release-contract for a comparison with pyfixest 0.60.0 (#1732, #1476, #1495).
  • Only the default demeaner is tested against fixest in the main test suite; the other backends run in a separate workflow (#1485).
  • Repository-local skills and developer guides for contributors and coding agents (#1476).
  • pixi.lock uses the v7 format, which needs pixi 0.71.0 or newer (#1498).
  • Internals: fitted models keep the formula ModelMatrix, the demeaning cache hands out read-only float64 arrays, and weighting happens inside the solver instead of on stored arrays (#1499, #1516, #1520).

PyFixest 0.60.0

This release focuses on the fixed-effects demeaning stack. The main changes are a typed demeaner API, switching from numba to Rust for the default MAP demeaning algorithm, reusable within preconditioners, PyTorch-backed LSMR demeaning on CPU and GPU, and a few deprecations for older backend options. It also adds fepois() offsets, Typst output for etable(), and several panelview() fixes.

Rust MAP Default and Optional Numba

MapDemeaner() now defaults to backend="rust". The Numba MAP backend remains available via MapDemeaner(backend="numba"), and the fast randomization-inference path (fit.ritest(..., choose_algorithm="fast")) still uses Numba. Numba is now an optional dependency installed with pip install pyfixest[numba].

Typed Demeaner API

A new typed demeaner API replaces the old demeaner_backend, fixef_tol, and fixef_maxiter arguments to feols(), fepois(), and related functions. Instead of passing a set of loosely related keyword arguments, you can now pass a configuration object that makes the chosen algorithm, tolerance, iteration limit, and device explicit.

import pyfixest as pf
from pyfixest.demeaners import MapDemeaner, LsmrDemeaner

# Old API (deprecated)
fit = pf.feols("Y ~ X1 | f1", data=df, demeaner_backend="rust", fixef_tol=1e-8, fixef_maxiter=5000)

# New API
fit = pf.feols("Y ~ X1 | f1", data=df, demeaner=MapDemeaner(backend="rust", fixef_tol=1e-8, fixef_maxiter=5000))
fit = pf.feols("Y ~ X1 | f1", data=df, demeaner=LsmrDemeaner(backend="within", fixef_atol=1e-8, fixef_btol=1e-8, fixef_maxiter=5000))
fit = pf.feols("Y ~ X1 | f1", data=df, demeaner=LsmrDemeaner(backend="torch", device="cuda"))

Deprecations: The demeaner_backend, fixef_tol, and fixef_maxiter arguments to feols() and related functions are deprecated and will be removed in a future release. The _fixef_tol and _fixef_maxiter attributes on fitted model objects are removed; going forward, this information is collected from the typed fit.options.demeaner via fit.options.demeaner.fixef_tol and fit.options.demeaner.fixef_maxiter.

Default change: LsmrDemeaner() now defaults to fixef_maxiter=1_000 (previously inherited 10_000 from BaseDemeaner). LSMR typically converges in far fewer than 1,000 iterations, but if you hit "Demeaning failed after 1000 iterations" on a difficult problem, pass LsmrDemeaner(fixef_maxiter=10_000) (or higher) explicitly.

The lower-level pyfixest.core.demean.demean_within(...) helper also tightened its default tol from 1e-6 to 1e-8. Calls through LsmrDemeaner already pass max(fixef_atol, fixef_btol) (default 1e-8), so the new default matches what the typed API was already using. Only direct callers of demean_within(...) with no tol argument see a behaviour change.

Diagonal Preconditioner for the within LSMR Backend

PyFixest now bundles version 0.2.0 of the within Rust solver, which adds a diagonal (Jacobi) preconditioner. You can use it with LsmrDemeaner(backend="within", preconditioner="diagonal"), alongside the existing "additive" (default) and "off" options.

Reusing Preconditioners

The within LSMR backend now exposes its additive Schwarz preconditioner so the (potentially) expensive setup phase can be amortised when users explicitly reuse it across regressions based on the same fixed-effect design.

import pyfixest as pf
from pyfixest.demeaners import LsmrDemeaner

df = pf.get_data()

# Every Feols-family fit exposes the preconditioner that was used.
fit = pf.feols("Y ~ X1 | f1 + f2", data=df, demeaner=LsmrDemeaner())
pre = fit.preconditioner

# Pass it back via `LsmrDemeaner(preconditioner=...)` to skip the setup
# phase on a later fit over the same design.
fit_fast = pf.feols(
    "Y ~ X1 + X2 | f1 + f2",
    data=df,
    demeaner=LsmrDemeaner(preconditioner=pre),
)

For fepois() and feglm(), the first IWLS iteration builds the preconditioner and every subsequent iteration reuses it under the changing working weights. That means the reused preconditioner is “stale” because it was built under the initial iteration’s weights. LSMR still converges to the correct demeaned values, but it may take a few extra iterations per IWLS step. The setup phase is paid once instead of once per IWLS iteration.

Each Preconditioner also reports its original setup time via preconditioner.build_time_seconds, which can be useful when profiling large fixed-effect problems. Preconditioner instances are pickleable, so the setup phase can also be amortised across Python sessions. See Choosing a Demeaner Backend for details.

PyTorch LSMR Backend

PyFixest now includes an experimental PyTorch-backed LSMR demeaner. It supports CPU execution, CUDA GPUs, and Apple Silicon MPS:

fit = pf.feols(
    "Y ~ X1 | f1 + f2",
    data=df,
    demeaner=pf.LsmrDemeaner(backend="torch", device="cuda"),
)

Install the optional dependency with pip install pyfixest[torch]. For CUDA, you may need to install a CUDA-enabled PyTorch build separately, following the PyTorch installation instructions.

JAX, CuPy, and SciPy Backend Deprecations

The jax MAP demeaner backend, the cupy / scipy LSMR demeaner backends, and the solver="jax" OLS solver option are deprecated and will be removed in a future release. Passing any of them now raises a DeprecationWarning.

We recommend the following replacements:

  • JAX MAP on CPU → MapDemeaner() (the default rust MAP).
  • JAX MAP on GPU or LsmrDemeaner(backend="cupy", device="cuda") → LsmrDemeaner(backend="torch", device="cuda").
  • Scipy or Cupy LSMR on CPU → LsmrDemeaner() (the default within backend).

Regression Compression Deprecation

The use_compression argument to feols() is deprecated and no longer supported. This feature implemented the in-memory regression compression approach from Wong et al. (2021) via a Mundlak/sufficient-statistics transform, and the implementation has now been removed. For large-dataset use cases, the duckreg package provides a more general out-of-memory solution. See #1302 for context.

Passing use_compression=True now raises a NotImplementedError.

Offsets in fepois()

pf.fepois() now supports offsets via the new offset argument. This is useful for Poisson models with an exposure term, such as offset="log_population". Thanks to @bradhackinen and @marie-gar for the contribution.

etable() Typst Output and Formatting

pf.etable() now supports type="typst" output. Its default coef_fmt is also inherited from maketables, which keeps PyFixest closer to the table engine it uses internally. As before, significance stars are controlled by the coefficient format string: include * on a statistic token, for example b:.3f*, when you want stars in the rendered table.

panelview Bug Fixes

  • Validates that the treat column is binary ({0, 1, True, False}) and normalizes it to boolean before plotting, matching R’s panelView behavior. See #1311.
  • Fixes sort_by_timing to sort units by the period of first treatment (via argmax) rather than by the total number of treated periods.
  • Raises an explicit ValueError when the treat column contains missing values instead of silently dropping them.
  • Fixes a latent bug in _plot_panelview where passing a user-supplied ax together with legend=True referenced an unbound figure variable; the colorbar is now attached via ax.figure.

New Demeaner Backend via the within package

We recently came together for a PyFixest sprint with the team from AppliedAI, and one new feature that already made it’s way into the code base is a new typed demeaner configuration that performs really well for sparse fixed effects structures.

The new solver is exposed via pf.LsmrDemeaner(backend="within") and is a significant performance improvement for sparse fixed effects structures - such as matched employer-employee data, patient-doctor panels, or trade networks - where the standard MAP algorithm might struggle. On well-connected graphs, pf.MapDemeaner(backend="rust") remains competitive, but on sparse graphs the within-based solver is dramatically faster.

Migration to maketables

The table functionality in pyfixest now uses maketables. maketables is a spin-off of pyfixest internal functions, but supports more packages in the Python eco-system (e.g. statsmodels and linearmorels). Due to it’s close connection to pyfixest, the API of pf.etable() remains unchanged. Changes:

  • pf.etable() now uses maketables.ETable internally. The API remains unchanged for backward compatibility.
  • Because the function is not at the core of pyixest functionality, we will deprecate pf.dtable(). A FutureWarning is now emitted. The function has been moved to maketables and can be used by calling maketables.DTable() directly.
  • The same applies for pf.make_table(), which has been an internal utility function to create tables. An equivalent function now lives in maketables.MTable().

PyFixest 0.40.1

Breaking Changes for compatibility with fixest 0.13

fixest 0.13 has recently been released to CRAN, with a range of breaking changes. We are following these in pyfixet 0.40.0.

  • The default inference method is now always “iid”. Before, both fixest and pyfixest would default to cluster by the first fixest effect in the presence of fixed effect.
  • The arguments of the pf.ssc() functions have been renamed: adj becomes k_adj, fixef_k becomes k_fixef, cluster_df becomes G_df, and cluster_adj becomes G_adj. Backwards compatibility is ensured.
  • fixest no longer applies the G/(G-1) small sample correction for heteroskedastic errors. The argument is now only relevant for cluster robust errors.
  • If the k_adj arg is set to True with heteroskedastic errors, the applied small sample correction now is N / (N-k) and no longer (N-1) / (N-df_k), as was previously the case and is still the case for iid and cluster robust errors.
  • The k_fixef option "nested" has been renamed to "nonnested".
  • The fixef_rm argument is changed from default "none" to "singleton" for all estimation functions. This has no impact on point estimates, but might change inference due to a smaller number of observations in the degree of freedom correction.
  • The multicollinearity default tolerance has been reduced from 1e-10 to 1e-09.
  • The attribute _dof_k has been renamed to _df_k.

Other related changes: - The arguments to adjust the small samples for the wildboottest methods have been renamed to k_adj and G_adj.

Moved to pixi.toml and install from conda-forge

  • We add options fixef_k = "nested" and fixef_k = "full" for computing small sample corrections via pf.ssc().   • We fix a small bug in the Gelbach decompose() method, which would fail if a user selected only_coef = True.

  • The decompose() method runs fully on sparse matrices, which leads to large performance improvements on big data sets.

  • We fix a small bug in the predict() method with newdata, see here for details.

  • We add a function argument rename_models to help rename model names in the coefplot() and iplot() functions and methods:

    pf.coefplot(

PyFixest 0.9.1

Breaking API changes

It is no longer required to initiate an object of type Fixest prior to running Feols or fepois. Instead, you can now simply use feols() and fepois() as functions, just as in fixest. Both function can be found in an estimation module and need to obtain a pd.DataFrame as a function argument:

from pyfixest.estimation import fixest, fepois
from pyfixest.utils import get_data

data = get_data()
fit = feols("Y ~ X1 | f1", data = data, vcov = "iid")

Calling feols() will return an instance of class Feols, while calling fepois() will return an instance of class Fepois. Multiple estimation syntax will return an instance of class FixestMulti.

Post processing works as before via .summary(), .tidy() and other methods.

New Features

A summary function allows to compare multiple models:

from pyfixest.summarize import summary
fit2 = feols("Y ~ X1 + X2| f1", data = data, vcov = "iid")
summary([fit, fit2])

Visualization is possible via custom methods (.iplot() & .coefplot()), but a new module allows to visualize a list of Feols and/or Fepois instances:

from pyfixest.visualize import coefplot, iplot

The documentation has been improved (though there is still room for progress), and the code has been cleaned up a bit (also lots of room for improvements).
